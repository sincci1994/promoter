# B4. Team Builder

> [MVP 화면 목록](../mvp-screens.md) 소속 — 디자인 생성 시 [공통 규약](_common.md)과 함께 입력
> Buyer · 데스크탑 · `/buyer/events/[id]/team` · 진입: [B3] 완료 직후, [B7] "재추천"

**목적**: **플랫폼의 핵심 UX.** 추천된 팀을 확인하고 사람을 교체하면서 총액 변화를 실시간으로 본다. 전화·메신저·사진 전달로 하던 인력 교체를 화면 하나로 바꾼다.

- **레이아웃**: 3영역. ① 좌측 메인 — Role별 섹션(Role 이름·요구조건 요약·충원 카운트), 섹션 안에 **자리 카드** 그리드: 사진(대형, 세로형), 이름, 등급 배지, 검증 자격 배지, 매치 표시(요구조건 충족 여부), 단가 `₩24,000/h`·이 행사 예상액. 빈 자리는 점선 카드(후보 찾기). ② 카드 액션 — 교체(하단 시트/팝오버로 **교체 후보 리스트**: 같은 Role 조건의 후보 3~5명, 사진·단가·매치 비교, 선택 시 스왑), 제거, 프로필 상세(→[B5] 사이드 패널). ③ 우측 고정 **견적 패널** — Role별 소계, 총 예상 금액(교체 즉시 갱신 — 클라이언트 재계산, 저장 없음 D5), 인원 요약, 하단 CTA "예약 요청하기" → [B6].
- **데이터**: EventRole, Assignment(Selected), 추천 후보(RecommendationRun 로그 — Rule 기반: 가용일정·활동 지역·등급·자격 필터), WorkerProfile, 견적(실시간 계산).
- **상태 변형**: 추천 로딩(자리 카드 스켈레톤), **후보 부족 빈 상태**(자리별 "조건에 맞는 후보가 없습니다 — 조건 완화 제안: 최소 등급 낮추기/태그 제거", [B3]로 이동 버튼 — 단 첫 요청 전만), 재추천 실행 중.
- **액션 → 전이**: 후보 담기/스왑 {Assignment: 생성→Selected}, 제거·교체 시 기존 카드 {Selected→Removed}. 재추천 = RecommendationRun 새 실행(로그 append). "예약 요청하기" → [B6].
- **정책**: 매치 점수의 노출 형태(High/Mid 라벨 vs 숫자) `[정책]`, Buyer에게 단가 세부 공개 범위 `[정책]`.
