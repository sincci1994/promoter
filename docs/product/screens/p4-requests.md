# P4. 요청·지원 목록

> [MVP 화면 목록](../mvp-screens.md) 소속 — 디자인 생성 시 [공통 규약](_common.md)과 함께 입력
> Worker · 모바일 · `/p/requests` · 진입: 탭 바, 알림 랜딩(복수 요청·지원 결과)

**목적**: 응답해야 할 요청, 승인 대기 중인 지원, 지난 이력을 관리한다.

- **레이아웃**: 탭 3개 — **응답 대기**(카드: 행사명·브랜드·일시·장소(지역 수준)·Role·단가·카운트다운, Emergency는 red 테두리+프리미엄 강조, 임박순 정렬) / **내 지원**(D6 — Application 카드: 행사·일시·지원 당시 표시 단가, 상태 배지 "검토 대기" — 정원 충족 시 "대기" 변형 `[정책]`, 같은 행사 복수 Role 지원은 카드 병렬 표시, 카드 액션 **철회** {Open→Withdrawn}) / **지난 이력**(거절·만료·철회된 요청 + 반려·만료·마감·철회된 지원 통합 — 상태 배지, 마감은 사유 라벨 병기(행사 취소/다른 역할 승인/모집 종료 등 — closed_reason 전 사유), 흐린 처리).
- **데이터**: Assignment(Requested / 종결 이력), Application(Open / 종결 이력), PriceSnapshot 요약.
- **상태 변형**: 탭별 빈 상태(내 지원 빈 상태는 "공고 둘러보기" → [P9]). 만료 임박(1시간 미만) red.
- **액션**: 요청 카드 → [P5]. 지원 카드 → [P5 공고 변형].
