# B1. Buyer 홈 — 활성 행사·주의 항목

> [MVP 화면 목록](../mvp-screens.md) 소속 — 디자인 생성 시 [공통 규약](_common.md)과 함께 입력
> Buyer · 데스크탑 · `/buyer` · 진입: 로그인 후 기본, 전역 내비 "내 행사"

**목적**: 지금 주의가 필요한 것과 진행 중인 행사를 트리아지한다. Buyer는 저빈도(브랜드 담당자)든 고빈도(대행사)든 동시 활성 행사가 소수이므로 홈은 목록 탐색이 아니라 입구다 — 관제탑은 [B7], 편의 기능은 [B2]부터.

- **레이아웃**: 상단 헤더(새 행사 만들기 버튼 우측 고정) + 3단 세로 구성. **필터 탭 없음.**
  ① **주의 필요 스트립**(해당 항목 있을 때만): 만료 임박 요청 n건 · 결원 발생 · D-1 미확인 n명 · **지원 검토 대기 n건**(D6) — 각 항목이 해당 행사 [B7] 딥링크.
  ② **진행 중인 행사**(Draft~InProgress): 세로 대형 카드 스택. 카드: 행사명·브랜드, 일시·장소, Event 상태 배지 + Booking 파생 상태 배지, 충원 게이지(충원 n / 유효 정원 m), 주의 플래그 + **상태별 다음 액션 버튼**(Draft→"역할 구성 이어서"[B3], TeamBuilding→"팀 구성"[B4], BookingPending→"응답 현황"[B7]). 당일(InProgress) 카드는 [B8] 직행.
  ③ **지난 행사**(Completed/Cancelled): 컴팩트 행 리스트(행사명·일시·결과 배지), 연도 구분선, 행 클릭→[B7] 읽기 전용. 행 액션 "같은 조건으로 새 행사" → [B2] 프리필.
- **데이터**: Event, Booking(파생 상태), 충원 projection, Attendance Risk 수, 지원 현황 projection(open_applications 합).
- **상태 변형**: 빈 상태 = 저빈도 Buyer의 사실상 첫 화면 — 첫 행사 만들기 CTA + 3단계 프로세스 안내(행사 만들기 → 팀 구성 → 요청 발송). 검색·상태 필터는 목록이 실제로 길어질 때(post-MVP).
- **액션**: 카드 → [B7]. 새 행사 → [B2].
