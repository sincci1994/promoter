# P9. 공고 탐색 — 날짜별

> [MVP 화면 목록](../mvp-screens.md) 소속 — 디자인 생성 시 [공통 규약](_common.md)과 함께 입력
> Worker · 모바일 · `/p/jobs` · 진입: 탭 바, [P1] 빈 상태 "공고 둘러보기"

**목적**: 날짜를 고르면 그날 모집 중인 공고를 보고 지원한다(D6). 받은 요청(P4)이 push라면 여기는 pull — 일이 없는 날을 채우는 화면.

- **레이아웃**: ① 상단 **주간 날짜 스트립** — 가로 스와이프, 날짜 셀(요일·일자·공고 수 도트, 터치 타깃 44px), 기본 선택 오늘, 월 점프는 네이티브 date input ② 선택일 공고 카드 리스트 — 행사 유형, 일시, 장소(지역 수준), Role 이름, **본인 Grade 기준 예상 단가** `₩24,000/h`, 모집 잔여(**= §8 remaining — 점유 기준: 유효 정원 − 활성 배정**. 지명·담김이 점유 중인 자리는 빈자리로 보이지 않는다. **remaining 0 공고도 모집 중이면 노출** — "대기 지원" 라벨 `[정책]`, [P5 공고 변형]의 Standby 접수와 짝), 이미 지원한 공고는 상태 배지(검토 대기 / 정원 충족 시 "대기" `[정책]`) 표시 ③ 지역 필터 1개(활동 지역 기본값).
- **데이터**: 모집 중 EventRole(파생 predicate — 행사 시작 시각 전만, I11), 충원 projection(remaining), 본인 Grade 계산 단가(열람은 저장 없음, 지원 시점에 표시가 기록 — D6), 내 Application 상태.
- **상태 변형**: 선택일 공고 없음 빈 상태("이 날짜엔 공고가 없어요" + 가용일정 등록 유도 → [P3]), 로딩 스켈레톤.
- **액션**: 카드 → [P5 공고 변형](p5-request-detail.md)(`/p/jobs/[roleId]`).
- **정책**: 공고 노출 범위(브랜드명 익명화 여부) `[정책]`, 정렬 기준(단가/거리/임박) `[정책]`.
