> [MVP 화면 목록](../mvp-screens.md) 소속 — 디자인 생성 시 [공통 규약](_common.md)과 함께 입력
> Buyer · 반응형 · 라이트 테마 · `/post` · 진입: 전역 공용 헤더 "공고 등록"(랜딩 포함 전 페이지), 홈 Buyer 미니폼 "팀 견적 미리보기"(유형·일자·인원 쿼리 프리필)
> **상태: 목업 구현됨(2026-08-09)** — `src/app/post/page.tsx` + `src/components/post/post-flow.tsx`, 후보 풀 `src/lib/buyer-flow-content.ts`(가상 100명 — 필터·견적은 실제 클라이언트 계산)

**목적**: "올리면 구해진다"의 본체. 기존 구인보드는 "쓰고 기다림"이지만, 여기서는 쓰는 **동안** 플랫폼이 먼저 반응하고(후보 수·견적 실시간) 쓰기가 끝나는 **순간** 결과물(추천 팀 초안)이 나온다. 도메인 정합: 플로우의 실체는 행사 등록(Event→Role 구성)이고 공개 모집은 Role 단위 토글(D6) — 라벨만 시장 언어("공고 등록").

- **레이아웃**: 4스텝 스텝퍼 + 우측 sticky **라이브 매칭 패널**(모바일: 하단 고정 바 — 후보 수·총액·다음 버튼).
  ① **기본 정보**: 행사명·유형·일자·근무 시간·지역·장소 — 입력 즉시 패널에 "8/22(토) 서울 — 가용 등록 프로모터 n명"(날짜·지역 바꾸면 변동)
  ② **역할 구성**: Role 카드(이름 datalist 프리셋·인원·최소 등급 select(등급별 단가 병기)·필수 자격 토글 칩(자격당 +₩2,000/h)) — **핵심 아하 1**: 행 하단 "조건 충족 후보 n명 · 예상 ₩x/h"가 조건 변경에 실시간 반응(후보<인원이면 red). 조건이 좁으면(후보 < 인원×2) amber 완화 힌트 "'영어 회화'를 우대로 바꾸면 n명". 역할 추가(최대 4)·삭제
  ③ **모집 방식**: "추천 팀 받기" = 기본(green 배지, D6 순서), "공개 모집도 함께 열기" = Role별 체크 — 켜면 홈 공고 카드 모양 그대로 미리보기 + **I7 잠금 고지**(amber): "첫 요청 발송 또는 공개 게시 후에는 일시·장소·역할 조건을 바꿀 수 없어요"
  ④ **발행 → 팀 초안**(핵심 아하 2): 1.2초 "추천 팀 구성 중…" 연출 후 Role별 후보 카드 보드 — 이니셜 아바타·이름·Grade 배지·자격·완료/재의뢰 수·**후보 본인 등급 기준 단가**. [교체] → 우측 시트에 대안 3명(미배정 상위) → 교체 시 총액 즉시 갱신. 후보 부족 시 amber "후보 부족 n자리 — 조건 완화 또는 공개 모집" 카드. 하단: "다음에 일어날 일" 체크리스트 + 진행 타임라인(요청 발송 시 2단계로 전진)
- **가격**: 발행 전 = 최소 등급 가정 총액, 발행 후 = **배정 후보의 실제 등급 합산**(Team Builder 실시간 견적, D5 — 저장 없음). "산출 근거 보기" 다이얼로그: 후보별 라인아이템(Base + 자격 가산 × 시간) + 고지 2줄("예상 금액", "요청·승인 시점 동결")
- **데이터**: 후보 풀 100명 결정적 생성(등급 4:3:2:1, 자격·지역·가용일 분포 — 주기를 등급 주기와 서로소로 설계해 쏠림 방지), §9 가격 테이블(정책 가설 수치)
- **상태 변형**: 발행 중 로딩, 후보 0/부족, 요청 발송됨(목업 시연 라벨)
- **정책**: 후보 익명화 수준 `[정책]`(목업은 가상 실명), 응답기한 `[정책]`, Role별 지원자 상한 `[정책]`
- **실구현 시**: RecommendationRun 로그·Event/EventRole 생성·PriceSnapshot 동결은 서버 몫 — 이 화면의 계산은 표시용(D5)이므로 API 교체 지점은 buyer-flow-content 하나
