# P5. 요청 상세 — 수락/거절 (+공고 변형: 지원)

> [MVP 화면 목록](../mvp-screens.md) 소속 — 디자인 생성 시 [공통 규약](_common.md)과 함께 입력
> Worker · 모바일 · `/p/requests/[id]` (공고 변형: `/p/jobs/[roleId]`) · 진입: [P4], **알림톡/SMS 딥링크(주 진입로)**, [P9] 공고 카드

**목적**: 조건을 보고 수락/거절을 결정하는 거래의 순간. 조건(무엇을·언제·어디서·얼마에)이 스크롤 없이 파악되어야 한다.

- **레이아웃**: ① 상단 고정 카운트다운 바 ② 행사 정보 — 행사명·브랜드·유형, 일시(소요 시간 병기), 장소, Role 이름·업무 설명, 요구 태그 ③ **금액 카드** — 라인아이템(기본 ₩24,000/h × 8h, 자격 프리미엄, 행사 프리미엄, 고정수당 `[정책]`) + **총 예상 금액 강조**. "요청 시점 금액으로 동결됩니다" ④ 하단 고정 듀얼 버튼: 거절(외곽선) / **수락**(채움, 대형).
- **Emergency 변형**: 상단 red 배너 "긴급 대체 요청", Emergency Premium 라인 강조, 짧은 기한, "지금 출발 가능할 때만 수락해 주세요" + 도착 예상 입력(선택).
- **공고 변형**(D6, `/p/jobs/[roleId]`): 카운트다운 바 없음(모집 마감 표기 `[정책]`), 금액 카드 라벨 "본인 등급 기준 예상 — **승인 시점 금액으로 동결됩니다**"(표시가보다 낮아지면 재확인 고지 `[정책]`. 지원 시 표시 금액·정책 버전·등급이 서버에 기록됨 — D6 감사 필드). 하단 CTA 단일 **지원하기** {Application: 생성→Open}. 같은 행사의 다른 Role 지원 가능(I10 — 행사당 상한 `[정책]`, 도달 시 비활성). 기존 일정과 겹치면 소프트 경고 시트("겹치는 근무가 있어요 — 승인 시점에 다시 검사됩니다", 지원은 가능). 이미 지원한 공고 재진입 시 상태 배지 + **지원 철회** {Open→Withdrawn}. 모집 마감 시 버튼 비활성. **정원 충족 공고는 "대기 지원"**(Standby — "정원이 찼지만 결원 시 승인될 수 있어요" 고지 후 접수) `[정책]`.
- **데이터**: Assignment(Requested), PriceSnapshot 라인아이템, Event/EventRole 요약. 공고 변형: 모집 중 EventRole(§8 파생)·본인 Grade 계산 단가(동결 아님)·내 Application 상태.
- **액션 → 전이**: 수락 {Requested→Accepted} — **시간 겹침(I6) 실패 시**: "같은 시간대에 이미 수락한 근무가 있어요" 시트(겹친 근무 표시, 먼저 수락한 쪽 유지 A3). 거절(사유 선택 시트: 일정/거리/단가/기타) {Requested→Declined}. 만료 후 진입 시 만료됨 상태(버튼 비활성).
- **정책**: 거절 사유 수집 항목 `[정책]`, 장소 상세 공개 시점(수락 전 지역 수준/수락 후 상세) `[정책]`.
